# Campus Maintenance Requests — Frontend (Activity 6)

ICT251 Web Technologies, Mulungushi University
Musenga Hope Sichula, 202511308

A browser interface where students report faults on campus (dead sockets, leaking taps, damaged
furniture, faulty appliances and more) to the Campus Help Desk and track each report until it is fixed. Built with plain HTML5, CSS and
JavaScript. This version stores **demonstration records in the browser with localStorage**.

## Files

| File | Purpose |
|---|---|
| `index.html` | Page sections (Home, Manage Records, About), form and record display area |
| `css/styles.css` | Colours, spacing and responsive layout (dark theme by default, light theme option) |
| `js/app.js` | Form events, validation, search, filter, messages and page updates |
| `js/data.js` | `recordService` with async `list`, `get`, `create`, `update`, `remove` using localStorage |
| `js/config.js` | Backend address, filled in for Activity 8 |

## Record structure

| Field | Rule |
|---|---|
| `id` | Positive whole number, generated by the data service, not editable |
| `reporter_name` | 2 to 80 characters |
| `student_number` | 6 to 12 digits |
| `location` | 3 to 100 characters, e.g. "Room B12, Block B" |
| `title` | 3 to 80 characters |
| `category` | 2 to 40 characters (Electrical, Plumbing, Furniture, Appliances, IT & Network, Building & Grounds, Other) |
| `description` | 5 to 300 characters |
| `status` | `Pending`, `In progress` or `Completed` |

Text is trimmed before its length is checked. Twelve made-up starting reports (names and student numbers are invented) are added only the
first time the page runs in a browser; an emptied list stays empty after a refresh.

## Run locally

The scripts are JavaScript modules, so open the folder with a local server such as VS Code
Live Server (right-click `index.html` → Open with Live Server).

## How to test

1. Submit the empty form, or only spaces → error messages appear and nothing is saved.
2. Enter a student number with letters or fewer than 6 digits → it is rejected.
3. Send a valid report and refresh → it is still there.
4. View, then Edit a report → the same report changes and keeps its id. Cancel edit leaves it unchanged.
5. Delete, then cancel the confirmation → the report stays. Confirm → it is removed.
6. Search by title and filter by status → only matching reports show, and the count updates.
7. Check the page at 375 px and 1280 px widths, and operate the form with Tab and Enter.
